# Qball 自我进化说明:改进 Agent,而不是训练模型

> 本文是 Qball 自我进化机制的权威说明。核心原则只有一句话:
> **我们从不训练模型权重;我们让模型反复去"用 Agent 干活",然后改进 Agent 本身。**

## 0. 先划清界限:两种"训练"的区别

| | 模型训练(**我们不做**) | Agent 进化(**我们做的**) |
|---|---|---|
| 改的对象 | 大模型的权重参数 | Agent 的工作方式:行为规则、技能库、代码 |
| 需要什么 | GPU 集群、训练框架、大规模数据 | 一台普通电脑 + 一个云端 API Key |
| 模型本身 | 会被替换成新的权重文件 | **永远是你配置的那个云端模型,一个字节都不改** |
| 变强的原因 | 模型"天生"变强 | 同一个模型,配上更好的 Agent 脚手架,干得更好 |
| 成本 | 昂贵、周期长 | 每天几分钱的 API 调用 |

一句话:**模型是固定的大脑;我们训练的是"这个大脑使用自己身体(工具、记忆、流程)的方式"。**

## 1. 什么是"Agent"(被改进的对象)

Qball 的 Agent 由四部分组成,它们就是进化的全部目标:

1. **人格与纪律** `agent/system_prompt_addendum.md` —— 任务执行时的行为规则,由它自己从成败中总结
2. **技能库** `agent/skills/*.md` —— 沉淀下来的操作套路(何时用、步骤、坑)
3. **记忆** `agent/memory/journal.md` —— 每代的反思日志
4. **代码**(白名单内的程序本体)—— 允许改,但受最严格的门禁保护

## 2. 进化循环(每一"代"发生什么)

```
派活(任务库:种子任务 + 它自己出的新题)
  → 执行(真实的它,用真实工具,在真实工作区里干活)
  → 评审(能自动验收的用验证器;软任务用评审模型打分)
  → 反思(写进记忆,之后的所有对话都会用上)
  → 提案(改规则 / 加技能 / 改代码)
  → 三道门禁(见下)
  → 采纳(本地 git 提交,可一键回滚)/ 丢弃
```

常驻后台运行,一代通常 1~3 分钟;任务库弱项不足时它会自己出题补货。

## 3. 三道门禁(为什么它不会把自己改坏)

1. **得分门禁** —— 本代得分 < 0.5 时,规则/技能改动**只记录不采纳**
   (防止"越失败越乱加规则"的膨胀循环)
2. **静态检查** —— 只允许改白名单路径;`tests/`、进化引擎自身、安装脚本、密钥等**永远只读**
3. **测试门** —— 改代码必须通过全套自动化测试(200+ 断言),全绿才提交,失败自动回滚

辅助保护:卡题自动跳过与退休(连败 5 次)、**知识自动合并**(规则/技能超限时去重压缩)、
连续失败熔断降频、长退避可被停止信号打断、附加指令体积上限。

## 4. 产物与版本(全部在本机)

| 内容 | 位置 |
|---|---|
| 进化工作区(自带 git 版本库,每次采纳 = 一次提交) | `~/.qball/evolution/` |
| 程序本体(git 仓库,采纳代码后自动重启生效) | 源码模式的 `~/.qball/app/` |
| 守护进程日志 / 得分曲线 / 每代留档 | `daemon.log` / `scores.jsonl` / `outcomes/gen-XXXX/` |

## 5. 怎么用

- 图形界面:设置面板 →「自我进化」(开关 / 暂停 / 跑一代 / 回滚上次 / 最近得分)
- 命令行:`qball evolve status | start | stop | pause | resume | once | revert`
- 前置条件:先 `qball dev-setup`(源码模式)—— 因为要能改代码,就必须运行在可修改的源码树上

## 6. 明确不做的事(防止跑偏)

- ❌ 不训练、不微调模型权重;不下载任何模型;不需要 GPU
- ❌ 不把用户数据上传去"喂模型"
- ❌ "为将来训练收集数据"**不是目标**;轨迹与得分只是进化的副产品,而且只留在本机
- ✅ 只做一件事:让模型 **反复使用 Agent**,把 Agent 改得越来越好
